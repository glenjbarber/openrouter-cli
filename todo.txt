## Confirmed working, recorded so it is not re-investigated

### Shift and up, and shift and down, page the pane

The chain is complete and each link has a test in
`internal/tui/pagekeys_test.go`.

- The modifier is read out of the parameters in `takeSequenceWithModifier`,
  `internal/tui/line.go`, and a shifted arrow is rewritten to `keyPageUp` or
  `keyPageDown` before it is queued.
- The key is handed to `OnKey` without being acted on in the editor,
  `internal/tui/keys.go`.
- `OnKey` is assigned in `Start`, `internal/tui/session.go`, and calls
  `s.page(-1)` or `s.page(1)`.

Only the shift is read. Alt, ctrl and meta pass through as the plain arrow, and
a sequence beginning with `<` or `M` is refused so that a mouse report cannot be
read as a page. This is the settled position in `AGENTS.md` under Tools, not a
gap.

### Delegate records nothing

`/delegate QUESTION` runs a second request from a copy of the conversation. The
answer joins the pane as ordinary text and to nothing else, so it does not
weaken the guarantee that `/cognito` makes. The prompt stays live while it
works.

## Open

### Multi-line mode cannot be left

**Observed.** Opening multi-line mode takes one Ctrl and J. Submitting the
block takes a second. No key cancels the mode.

**Where.** `internal/tui/line.go`, the `keyNewline` case. `breakLine` holds the
lines, `setMultiline(true)` sets the flag, and nothing else acts on it. Escape
does not clear it, since `le.pasted` is cleared only on a path that returns
without submitting.

**Why it matters.** A reader who opens the mode by accident, or opens it by
pasting text carrying a newline, cannot back out. Escape then sends a message
rather than abandoning the composition, which is the opposite of what escape is
recorded as doing on an idle prompt.

**What is needed.** A decision rather than a patch. The record gives escape two
meanings already, abandoning a line and stopping a model, and this would be a
third. The item in `IDEAS.md` under Backlog, `Ctrl-C cancels a queued message`,
names the same underlying problem: keys acting on a state the reader cannot
leave.

### A directory named with a tilde is not expanded

**Observed.** `isDirectoryArg` reads any argument carrying a separator as a
directory, and `filepath.Abs` does not expand `~`. A rule written from
`/permission add ~/work go` would be written against a literal path named `~`,
and would never match a directory at run time.

**Where.** `internal/tui/permission.go`, `permissionDir` and `isDirectoryArg`.

**Unconfirmed.** Whether the argument arrives expanded depends on the shell.
Where the shell expands it, the client receives an absolute path and the
directory is read correctly. This was not checked against a live shell, and the
item should not be treated as a defect until it is.

**What is needed.** A check on a real terminal first. If the shell does not
expand it, the fix is in the client rather than in the documentation.

### An argument given on the command line is discarded

**Observed.** `/search` and `/models` both parse their argument and drop it, so
`/search compaction` opens a search with an empty filter and `/models claude`
opens the catalogue unfiltered.

**Where.** Both handlers are `func (s *Session) cmdX([]string) bool`. The
finding is already recorded at length under Awaiting confirmation in
`IDEAS.md`, with four sub-questions left open.

**Status.** Open, and recorded rather than implemented, since the record settles
nothing about a query supplied on the command line.
